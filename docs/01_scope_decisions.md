# 01 · 需求、范围和设计决策记录

更新：2026-10-15。此处记录**用户决定**与**待核查问题**，不是制造完成证明。

## 使用场景

Pocket Pi 最初定位为随身携带的语音优先 Agent 客户端，不在 C5 上运行 Pi Coding Agent 或大语言模型。2026-10-16 已将长期定位扩展为 **Pocket OS 多 APP 触屏终端**：Pi 是可选 APP，另包括家庭相册、日语练习、儿童互动、HA 和本地 GB 模拟器等；参见 [08 软件选型与 APP 场景](08_software_architecture_and_app_roadmap.md)。既有家用 Linux 服务器承担语音处理、Pi 等服务接口；小屏负责录音、文字、触摸、APP 状态与摘要。使用 Wi-Fi 联网；手机热点能否访问家中 Pi 服务需另行验证（手机自身的 WireGuard 不保证热点客户端能访问内网）。

使用方式倾向**按一下开始录音、再按一下结束/发送**，而不一定需要长按 Push-to-Talk。触摸屏完成其余交互。BOOT 可被软件复用，复位和电源功能保持独立。

## 项目约束

- 材料和打印预算：目标人民币 200 元以内，成本需持续复核。
- DIY 外壳但不从零做主板；优先使用现成的微雪 C5 集成板及其原装声音、电源能力。
- 淘宝代打印，没有自有打印机，返工昂贵；必须 CAD 干涉检查、关键尺寸确认后才下单。
- 第一版使用预期约半年，不投入为极限按键手感/百万次寿命服务的复杂机构。
- 结构要尽可能简单、可靠、容易装配拆解，不靠胶水承受常规按钮负载。
- 已有 Pi Web / Pi Coding Agent 工作流，软件架构可复用，当前研发重点是工业设计和机械落地。

## 方向勘误（重要！）

先前讨论曾**错误地**把官方背面资源图与正面视觉左右关系混为一谈。用户明确纠正：

> 对**官方横向板载图向右旋转 90°**后，USB-C 在上、**麦克风在左侧、按键在右侧**。

**这是官方图的观察视角。** 反过来看正面时左右会镜像；任何外壳侧边键帽和麦克风开孔的实际 CAD 坐标均须以原版 STEP 和前/后视图重新验证，不能沿用先前助手的“正面在左侧”陈述。

详见 [02 硬件与方向](02_hardware_orientation.md) 和 [方向示意图](../assets/orientation_diagram.svg)。

## 未决项（不要提前改写成已确认）

- 电池套餐及实际长宽厚、保护板、导线出口、MX1.25 极性：等待客服回复。
- 麦克风元件的**声学开口方向**、距离哪一面/边多远；确认是直孔且不会被掌心遮挡。
- 选用原装喇叭的外形尺寸、固定方法和线长。
- 旋转后 BOOT / RESET / BAT_PWR **精确坐标、开关按钮头朝向、机械行程**；键帽是否能直接从侧面直线按动。
- 旋转后的屏幕与触摸坐标映射、启动时 BOOT 特殊行为的实机测试。
- 壳体设计尺寸、壁厚、公差、螺钉孔和装配顺序。
- 总成本与淘宝打印实际报价。
- 室外热点连接家庭服务器的认证/网络路径。

## 不进入 V1 的功能

- 两颗正面键、机械轴/旋钮/无线充电。
- 新增外部麦克风、长声道、复杂扬声器调音腔。
- 自制整机主 PCB、柔性 PCB；单纯为实现侧键增加控制电路。
- 未验证的 LED 导光、假想外置侧边键、摄像头。

## 更改决策的规则

如果实机发现原生 BOOT 长按不适合语音/按键位置不理想，先做低成本测试并追加 ADR；不要静默回退到外加两颗侧键或把正面双键重新混入 V1。
